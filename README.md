# Edge AI Enabled Motorcycle Quality Control System

## Overview

This project is a locally deployed, real-time quality control demo for motorcycle manufacturing inspection.

It reads live sensor data from an M5Stack device over serial, monitors abnormal noise and motion conditions, triggers a camera when warning conditions occur, processes the captured image with a simple vision pipeline, and sends the warning context to a local LLM for inspection feedback. The UI is built with Streamlit and displays live metrics, warning events, processed images, and AI responses.

## Module Responsibilities

### `module1_ui.py`
Streamlit frontend.

Main responsibilities:
- render sensor status cards
- render real-time indicators for:
  - `mic_rms` -> `Noise (dB)`
  - `acc_rms` -> `Linear Acceleration`
  - `gyro_rms` -> `Angular Acceleration`
- render live trend curves
- render triggered abnormal events
- render processed warning images
- provide manual `AI Agent Q&A`

This module does not decide when to trigger warnings. It only reads runtime state from `module2_serial.py` and displays it.

### `module2_serial.py`
Core runtime and system coordinator.

Main responsibilities:
- open and read the serial port
- parse incoming JSON data from the M5Stack
- compute:
  - `mic_rms`
  - `acc_rms`
  - `gyro_rms`
- apply threshold logic
- maintain shared state for the UI
- trigger warning events
- run background workers for:
  - camera capture
  - vision processing
  - LLM analysis
- save sampled data into CSV

This is the main control layer of the project.

### `module3_llm.py`
Local LLM interface.

Main responsibilities:
- build prompts for abnormal warning events
- build prompts for manual user questions
- call the local Ollama model
- return text feedback to `module2_serial.py`

Current usage:
- automatic warning analysis
- manual operator Q&A

### `module4_camera.py`
Camera capture module.

Main responsibilities:
- open the local camera with OpenCV
- warm up the camera
- capture one frame when triggered
- save the image into `captured_images/`
- return the saved image path

### `module5_vision.py`
Image processing module.

Main responsibilities:
- load the captured image
- run edge detection
- draw green contours or edge highlights
- save the processed result into `processed_images/`
- return the processed image path and a short summary

This module currently performs simple OpenCV-based edge visualization, not a full industrial defect detector.

## Runtime Data Flow

```text
M5Stack serial data
    ->
module2_serial.py
    ->
threshold check
    ->
warning event
    -> module4_camera.py
    -> module5_vision.py
    -> module3_llm.py
    ->
module1_ui.py
```

Detailed flow:

1. The M5Stack sends microphone and IMU data through the serial port.
2. `module2_serial.py` reads the data and computes `mic_rms`, `acc_rms`, and `gyro_rms`.
3. If any metric exceeds its threshold, a warning event is created.
4. A background worker is started so the serial loop can continue running in real time.
5. The worker:
   - captures an image with `module4_camera.py`
   - processes the image with `module5_vision.py`
   - sends sensor context to `module3_llm.py`
6. `module1_ui.py` keeps refreshing and displays:
   - live sensor values
   - warning events
   - processed images
   - LLM responses

## Key Shared Variables

The main monitored variables are:

- `mic_rms`: microphone RMS converted to `Noise (dB)`
- `acc_rms`: RMS of dynamic linear acceleration
- `gyro_rms`: RMS of angular motion

Thresholds are defined in `module2_serial.py`:

- `MIC_DB_THRESHOLD`
- `ACC_RMS_THRESHOLD`
- `GYRO_RMS_THRESHOLD`

## Important Runtime Behavior

### Real-time UI updates
The UI refreshes continuously and reads a shared runtime snapshot from `module2_serial.py`.

### Warning cooldown
Repeated warning triggers are rate-limited. After one warning event is triggered, the system waits a short cooldown period before allowing another trigger.

### Background processing
Camera capture, image processing, and LLM calls run in background threads so that serial monitoring and UI updates continue while slower tasks are running.

## Generated Files and Folders

### `captured_images/`
Stores raw images captured when a warning event occurs.

### `processed_images/`
Stores processed images generated by `module5_vision.py`.

### `core2_mic_imu_vibration_sound.csv`
Stores sampled runtime data written by `module2_serial.py`.

## How to Run

### Start the UI

```powershell
powershell -ExecutionPolicy Bypass -File .\start_ui.ps1
```

### Stop the UI

```powershell
powershell -ExecutionPolicy Bypass -File .\stop_ui.ps1
```

### Direct Streamlit launch

```powershell
python -m streamlit run module1_ui.py --server.port 8501 --server.headless true
```

## Notes

- The serial device is expected on `COM3` by default.
- The camera index is currently set inside `module4_camera.py`.
- The LLM path is local and depends on Ollama being installed and the target model being available.
- The current vision module is intentionally lightweight for demo use.
